# PAM Financial Systems — integration operating contract (construction draft)

**Scope:** portable interfaces for one coherent CC/IR/PI workflow; **not deployed**. Use this to create versioned Project instructions and request/report templates. Does not override existing CEO-protected investment policy or the approved Project v0.2 instructions until separately adopted. Manual transfer is the current verified fallback.

## 1. Request and strategy context

A request carries **only supplied or explicitly confirmed values**, not fabricated defaults for account/tax/FX costs:

```json
{
  "analysis_id": "user-selected-or-generated-ID",
  "as_of": "YYYY-MM-DD",
  "objective": "research | compare | portfolio_contribution | user_requested_followup",
  "strategy_id": "approved-strategy-and-version",
  "horizon": "explicit-user-horizon",
  "risk_constraints": ["supplied"],
  "universe": ["user holdings", "watchlist", "worldwide discovery as justified"],
  "account_context": {"type": "UNKNOWN", "broker": "UNKNOWN", "tax": "UNKNOWN", "commission": "UNKNOWN", "fx_cost": "UNKNOWN"},
  "portfolio_input": {"source": "NONE | authorized Blossom view | dated screenshot", "observed_at": null},
  "privacy": "PRIVATE",
  "output_budget": "executive <=10 minutes; detailed evidence on demand"
}
```

Missing decisive context is asked concisely or preserved as conditional `UNKNOWN`, never invented. High-CAGR's existing policies are not generalized to another strategy.

## 2. Reusable source-neutral fact record

```json
{
  "economic_entity": "evidence-backed identity",
  "instrument": "ticker/class/exchange/ADR-ratio only if known",
  "metric": "precise economic concept",
  "value": "number or null",
  "unit_currency": "unit and native currency",
  "start_end_or_quote_timestamp": "exact applicable period/date",
  "definition_basis": "US-GAAP / IFRS / issuer-adjusted / provider estimate",
  "source_url": "exact reference",
  "observed_at": "capture date",
  "publication_at": "if verified",
  "source_rights_status": "PERMITTED | UNCERTAIN | RESTRICTED",
  "verification_status": "VERIFIED | INDICATIVE | CONFLICTED | MISSING",
  "classification": "SOURCE_FACT | THIRD_PARTY_ESTIMATE | PAM_ASSUMPTION",
  "conflict_or_qualification": "explicit limitation or null"
}
```

If two sources disagree, compare accounting definitions, periods, currency, corporate-action basis and instrument identity; log both without selecting the higher-impact number. Data absence is **not** Quality failure. Providers are chosen per **fact needed**, not used as a universal company database.

## 3. Handoff, provenance, and report

`CC` creates a compact `IR_REQUEST` specifying needed facts, question, scope, strategy, expected output and source budget. `IR` returns `IR_CAPSULE` with `FACTS_VERIFIED`, `UNVERIFIED`, `ASSUMPTIONS`, `COUNTER_THESIS`, `VALUATION_SCENARIOS`, `EXPECTED_RETURN_STATUS`, `CONFIDENCE_RATIONALE`, citations and `NEXT_OWNER`. `PI`, only when requested portfolio inputs exist, returns a `PI_DELTA` with `VISIBLE_HOLDINGS`, `UNKNOWN_HOLDINGS`, `AS_OF`, `EXPOSURES`, `COST_INPUTS`, `CONTRIBUTION_WEIGHTS` and reasoned no-action/exceptional-trim decisions. `CC` checks coverage and synthesizes a final decision report, **without inflating evidence confidence**.

When IR has collected source observations, it may attach an optional **PRIVATE** `EVIDENCE_ANNEX` directly to the unchanged `IR_CAPSULE`: `{"analysis_id":"same-analysis-id","analysis_as_of":"request-YYYY-MM-DD","observations":[...]}` with the existing `ai_native.source_fusion` observation schema. M7a consumes this field automatically through both CC→IR→CC and CC→IR→PI→CC manual routes; no second source-entry argument is needed. If both embedded and separate annexes are supplied, reject rather than select silently. Reject mismatched identity/date, unknown IR fact IDs and observations occurring after `IR_CAPSULE.research_as_of`. Keep the complete original capsule unchanged when forwarding to PI; keep the resulting source/alignment annex private. Structural alignment does **not** establish authenticity, rights, PIT authority, independent verification or readiness.

Minimal shared envelope: `ANALYSIS_ID`, `PROMPT_VERSION`, `METHOD_VERSION`, `OBJECTIVE`, `AS_OF`, `SOURCE_REFERENCES`, `FACTS_VERIFIED`, `INTERPRETATIONS`, `ASSUMPTIONS`, `UNKNOWN_OR_DISPUTED`, `SCENARIOS`, `IMPACT_ON_DECISION`, `CONFIDENCE_RATIONALE`, `FURTHER_CHECK_REQUIRED`, `NEXT_OWNER`, `OUTPUT_BUDGET`. Transfer only the compact delta plus exact archive references; keep needed attachments when source locators are unavailable.

**Final report template:** (1) decision question and what was actually checked; (2) top conclusions and counter-arguments; (3) Quality/Durability/Expected Return/Confidence; (4) price and after-cost/portfolio implications **only if supported**; (5) missing decisive facts and recommended next action; (6) evidence annex reference. For a CEO-requested follow-up compare with the actual earlier analysis regardless of elapsed time, including thesis/invalidation changes and justified no-action. There is no scheduled or default weekly analysis. No auto-trading.

**Optional four-pillar research trace (M1→M2→M4):** The unchanged IR_CAPSULE may contain `PILLAR_ASSESSMENTS` with exact keys `{analysis_id, research_as_of, strategy_id, pillars}`. The `pillars` map must have exactly `QUALITY`, `DURABILITY`, `EXPECTED_RETURN`, `CONFIDENCE`, each with `{status, ir_fact_ids, rationale_private, countercase_private}`; status is `SPECIALIST_REPORTED` or `UNKNOWN`. A reported view needs original IR fact links, not invented numerical ratings. M7a links those facts to any supplied M5 structural alignment; absent/unresolved evidence remains `EVIDENCE_RESOLUTION`, aligned observations only become `HUMAN_RESEARCH_REVIEW_ONLY` (never certified). The M4 private report displays only per-pillar stage and reference counts; rationales/countercases stay in the private annex. Portfolio Room is handled separately by M3 using dated holdings and remains `NOT_EVALUATED` without them. The original IR capsule forwards unchanged via PI, no external facts or rights are authenticated, and there is no Quality/Durability grade, normalized Expected Return, overall score, VFV alpha, investability, action or trade authority. Synthetic test command: `python -B -m unittest -v tests.test_ai_native_pillar_trace`; full-system acceptance remains pending.

**PI-only capital route (M1→M3→M4):** A CEO-initiated portfolio-only request can now produce the same supplied gross/cost/funded contribution summary as the IR+PI path after the manual PI delta arrives, **without manufacturing an IR capsule**. The shared private calculator requires portfolio date parity; any incomplete supplied observation cannot be overridden by a contradictory complete-scope assertion. Research-only annexes remain unavailable without IR. No automatic holdings access or executable orders follow.

**CEO-requested historical research follow-up (M4):** a supplied prior private research case can now contribute a brief structural prior/current review to the private CC FOLLOWUP report. The status transitions of explicitly linked IR facts and same/different wording are reported without copying original claim text, certifying economic or thesis changes, assuming a missing baseline means stability, or hiding changed method/strategy comparability. Manual original-source and rights review remains necessary. No automatic archive access, scheduled research, GitHub public memory write or portfolio action.

**Candidate comparison reporting seam (M2→M4):** the existing 2–6-candidate M2 comparator now contributes a compact private CC report showing at most four pairwise BEAR/BASE/BULL first-minus-second annualized percentage-point scenario differences **only when bases are comparable**. Source/currency/quote-date/measure inconsistencies remain NOT_COMPARABLE. The report rechecks original M2 spreads against supplied individual scenario arithmetic; it is not a ranking, price target, probability-weighted Expected Return, VFV alpha or executable allocation. Full assumptions and all other pair comparisons remain private; no issuer/cost/portfolio data enters GitHub memory.

**Source-linked macro/sector research context (M2→M4, CEO decision 23):** For an explicitly CEO-initiated IR analysis, `macro_sector_inputs` accepts exact keys `{analysis_id, analysis_as_of, strategy_id, drivers}` with 1–8 drivers. Each driver supplies `{driver_id, scope, reported_effect, ir_fact_ids, source_observation_ids, hypothesis_private, countercase_private, next_check_private}`; `scope` is `MACRO` or `SECTOR`, and effect is one of `TAILWIND_REPORTED`, `HEADWIND_REPORTED`, `MIXED_REPORTED`, `UNKNOWN`. The original IR fact IDs and M5 source-observation IDs must match an existing, structurally checked source annex; unresolved, rights-uncertain, or secondary-only sources remain EVIDENCE_RESOLUTION. The CC report shows only limited driver IDs, caller-reported effect and the human research queue; causal narratives, countercases, sources and next checks remain private. There is no independently verified causality, macroeconomic forecast, ETF indicator computation, market-timing signal, expected alpha, candidate ranking or trade authority. Works across the existing IR-only or IR+PI manual route; no periodic research or automatic source access. Synthetic tests: `python -m unittest -v tests.test_ai_native_macro_sector_context`; authentic system acceptance remains pending.

**Research discovery/triage reporting seam (M2→M4):** after CEO-requested IR/source evidence is structurally assembled, M2 classifies only caller-supplied candidate research tasks into EVIDENCE_RESOLUTION and HUMAN_DEEP_DIVE. The private CC report now shows stage counts and at most eight candidate references **in submitted order, never ranked**. Unusable source observations, rights gaps and missing IR facts remain explicit research blockers. No global discovery, source authentication, normalized Expected Return, investability, automatic portfolio action or independent ranking is established. Detailed candidate rationale, economic issuer, source records and original research questions remain in the private annex, excluded from GitHub memory.

**Fundamental economics reporting seam (M2→M4):** a supplied IR source-annex and compatible original-source observations can produce a private two-period M2 dossier. M4 now shows **only descriptive, structurally comparable** reported revenue change, operating margins, CFO less cash capex (explicitly *not* normalized owner earnings), diluted-share changes, and specialist-reported qualitative-axis statuses. Noncomparable/missing pairs remain UNAVAILABLE; original sources, qualitative rationales and financial details remain in the private dossier, never in institutional GitHub memory. No independent source authentication, organic-growth conclusion, Quality/Durability verdict or Expected Return is implied.

**Research valuation reporting seam (M2→M4):** conditional BEAR/BASE/BULL scenario measures from the existing M2 arithmetic may appear in the **private** CC decision report. Each displays only its available annualized price-only CAGR, separately its conditional year-end cash-flow IRR when distributions are explicitly supplied, or UNAVAILABLE on unconfirmed security/currency basis. These alternative scenario calculations are *not* probability-weighted Expected Return, not a VFV alpha forecast and not proof of source authentication or investability; details and rationale stay in the private valuation annex. No valuation payload enters public GitHub memory.

**Source-to-valuation quote trace (M5→M2→M4):** Where an IR capsule carries the private `EVIDENCE_ANNEX`, existing `valuation_inputs.quote_source_ref` can be set to the exact `source_fusion` `observation_id` for a quoted `MARKET_PRICE_PER_SHARE` record (unit `PER_SHARE`; observation period start/end equal to `quoted_at`). The connected M7a path compares security identity, native quote currency, quote timestamp, and exact decimal price to the same original observation. Any mismatch is rejected, never substituted; a missing/mismatched reference or unusable/rights-uncertain/conflicted source stays `EVIDENCE_RESOLUTION`. When structurally consistent, `HUMAN_QUOTE_REVIEW_ONLY` still requires a person to verify the original exchange/quote source and terms, quote timestamp, liquidity, share class, adjustments and currency basis. A linked observation captured after `IR_CAPSULE.research_as_of` cannot be backdated. Without a supplied annex, scenario arithmetic remains available solely as conditional input math with a prominent source-resolution warning. The private M4 report shows **only** whether quotation provenance needs evidence resolution or human verification, never source locators, raw private quotes, a certified market price, net return, valuation confidence or trading permission. The direct `evaluate_valuation_scenarios` deterministic API is unchanged; the bridge only adds an optional source-reference cross-check. Synthetic tests: `python -B -m unittest -v tests.test_ai_native_valuation_quote_trace`. Real quote/source/rights acceptance remains pending.

**Portfolio Room reporting seam (M3→M4):** for an explicitly CEO-requested IR+PI mandate, a scoped private portfolio observation and qualitative Portfolio Room assessment now surface in the **private final CC report**: caller-reported four research pillars, four portfolio checks, supplied known issuer exposure as a conditional lower bound, unknown look-through, and a count of unresolved conditions. ROOM_CONDITIONAL/UNAVAILABLE is **not** investment admission, portfolio target weight or trade approval. **New-contribution reporting seam (M3→M4):** if a scoped, dated PI contribution projection is available, the private CC report may display up to eight **caller-supplied percentages of NEW capital**, never portfolio target weights. The report keeps cost/funding outcomes separate: gross only, conditionally reconciled supplied fixed fees, or unavailable. The summary excludes balances, purchase amounts and detailed cost quotes, and nothing is copied to public GitHub memory. More destinations stay in the private annex. No recommendation, authentication, executable order, or net Expected Return follows from this display.

**On-demand unified human review queue (M1→M2/M3/M4):** The existing private R1 CLI now accepts `--output review-queue`, explicitly selected by the operator. It consumes **only** the already assembled `complete_manual_session` output, ordered by real handoff state and structurally existing annex status: unavailable IR/PI handoffs; method-installation confirmation; missing original IR source annex or facts needing alignment; original-source/rights inspection; quote provenance resolution versus original-quote human check; scenario assumption review; portfolio scope and dated-holdings verification; new-contribution account cost confirmation; and final private-report review. Items contain fixed, code-generated action strings only (no account IDs, holdings, source URLs, source/fact IDs, prices, amounts, raw narratives or model verdicts), and the standard redacted `--output status` is unchanged. No fabricated source verification, new research, automatic Project invocation, scheduled monitoring, decision-grade assurance, order, archive or ready gate. Queue status `MANUAL_REVIEW_QUEUE_NOT_ACCEPTANCE` and `readiness=NOT_EVALUATED` remain explicit. The original IR capsule stays unchanged. Tests authored at `tests/test_ai_native_manual_review_queue.py`, canonical full-session execution/acceptance pending.

**Local manual R1 entrypoint (no service, no network):** from a trusted repository checkout, use `python -m scripts.r1_manual_session_cli --output status < private_case.json` to route an explicitly CEO-initiated request supplied as JSON, e.g. `{"request":{"ceo_initiated":true,"analysis_id":"TEST-LOCAL","as_of":"2026-10-28","kind":"DECISION","objective":"Synthetic review","research_needed":true,"portfolio_needed":false}}`. The top-level JSON object can additionally include `ir_capsule`, `pi_delta`, and other named `complete_manual_session` arguments; unknown fields, duplicate JSON keys, nonfinite numbers (**including exponent-overflow values such as `1e999`**) and input larger than 5 million characters are rejected. The default **status** output contains only non-sensitive stage/readiness/action codes. `--output handoffs` explicitly prints private IR/PI copy-ready packets for **manual** transfers; `--output report` prints the private conditional final Markdown report only after required handoffs. **Use a private terminal and protect any redirected output**; never paste personal holdings, access tokens, account IDs, or private reports into GitHub. The program does not read input files itself, persist data, log personal details, invoke Projects or contact Blossom, and it never trades. The local runner's standard-library test is `python -m unittest -v tests.test_ai_native_r1_manual_cli`; this is a *construction* path, not independent source verification or complete 36-decision acceptance.

## 4. Case and memory contract

Store significant research as dated, source-referenced and versioned **analysis/case records** with separate public/institutional method memory and protected private financial storage. Never put user holdings, account identifiers or brokerage data in ordinary GitHub records. Prompt improvements require a change rationale, relevant case comparison, human approval when material and non-hindsight outcome reviews.

**Explicit private case export for a later CEO-requested follow-up:** from the same trusted local checkout, supply `memory_inputs: {"report_id":"opaque-record-id","instruction_version":"explicit-version","recorded_at":"YYYY-MM-DD"}` alongside the full original IR capsule and request, then choose `python -m scripts.r1_manual_session_cli --output private-case < private_case_input.json`. The output is an unencrypted **PRIVATE PROPOSAL**, not a stored archive or rights-cleared publication. It includes the original research, source references and possibly identifying context; never paste it into GitHub, share it, log it, or redirect it to an unprotected/shared location. On an explicit later FOLLOWUP, the returned record can be supplied as `historical_comparison_inputs.prior_case` together with `subject_id` and analyst-selected fact-ID links. The original request must explicitly carry the same `subject_id`. No archive retrieval, encryption, case uniqueness assurance, automatic comparison, monitoring or method promotion is provided. Without `memory_inputs`, private-case output is withheld. The default redacted status is unchanged. The operator is responsible for any secure retention outside the repository.

**Manual integrated construction smoke — no acceptance claim:** `python -m unittest -v tests.test_ai_native_r1_integrated_smoke` (run only from an authentic local checkout) exercises real stdlib M1→M2→M3→M4→M7a functions with **synthetic-only** source/valuation/portfolio/fee inputs: user-requested CC→IR→PI→CC, evidence, research triage, scenario comparisons, scoped portfolio, qualitative Portfolio Room, new capital and private report. It asserts missing PI stays pending and source/identity/date errors fail closed, without mocking the assembler. `python scripts/ci_unittest_runner.py --tier STANDARD` is the existing broader suite. A passing synthetic smoke would demonstrate only constructed seams, **not** live Projects, Blossom, rights/authenticity, account finance, system-wide 36-decision acceptance, promotion or trades. No workflow/CI billing settings changed.
